# A-06 主存桥与缓存统计

`rv32_memory_bridge` 位于指令／数据缓存和双端口缓存行主存之间。指令、数据两侧各有一个独立的
单事务缓冲，因此两个端口可以在同一周期接受请求并分别等待响应。缓存请求只在
`cache_*_req_valid && cache_*_req_ready` 时被锁存；此后缓存行地址、128 位写数据、
16 位字节使能、读写属性和 8 位事务 ID 保持不变，直到主存完成事务。

桥不会把测试平台的字节数组直接暴露给缓存。合法请求在
`mem_*_req_valid && mem_*_req_ready` 握手后等待原端口响应；响应反压期间，返回地址、
数据、ID 和错误标志全部稳定。主存响应的地址或 ID 与已接受事务不匹配时，桥仍然消费该
响应，但向缓存返回原事务的地址／ID 和确定的错误，避免标记串线或死锁。

缓存行地址必须 16 字节对齐并落在 `MEMORY_SIZE` 范围内。未对齐或越界请求不发送到主存，
而是在对应缓存端口产生保留原 ID 的本地错误响应和全零数据。数据侧写请求完整转发
128 位数据与 16 位掩码；写入可见时刻仍由 H-03 主存模型的响应握手定义。

`rv32_cache_stats` 在复位时清零，之后只消费已定义的单周期事件。指令／数据侧的请求、命中、未命中、
回填、写回和停顿来自缓存；指令侧主存请求、数据侧主存读／写来自主存桥的
真实请求握手。冲刷不清除历史统计，也不会伪造一次请求或响应事件。

验证入口 `make a06` 覆盖真实 50 周期指令／数据侧并发、请求载荷锁存、响应反压稳定、数据侧写
掩码／小端序、原事务 ID 返回、本地异常终止、精确主存握手事件和全部统计计数器
的复位及逐沿计数，并执行 Verilator 与 Yosys 检查。
