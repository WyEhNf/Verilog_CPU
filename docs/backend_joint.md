# B-09 后端联合门

`rv32_backend_joint` 是 `BE_WIDTH=1/2/4` 参数化的多发射乱序后端闭环。输入和
`CommitRecord` 均为按通道压平的连续指令束；数据缓存侧直接复用 `rv32_lsq`
的请求、响应和存储确认协议，不建立第二套内存字段。

## 数据路径

重命名为每条轨迹分配 ROB 标记和物理目的寄存器。PRF 提供两个读口；当源
物理寄存器尚未写回时，联合门用 `phys_tag_mem` 保存其生产者 ROB 标记，RS 在
CDB 唤醒后再发射。立即数、分支预测信息和访存属性按 ROB 槽位保存，避免
轨迹输入撤销后改变已分派指令。

RS 每周期按年龄选择最多 `BE_WIDTH` 条就绪指令，每个通道有独立整数 ALU；
MUL/DIV 由一个共享 MDU 接受当拍最老的 M 类指令。ALU、MDU 和 LSQ 的加载完成结果
统一进入完成网络，再同时驱动 PRF、ROB 和 RS 唤醒。ROB 只在队首
产生最多 `BE_WIDTH` 条连续提交记录；存储必须成为通道 0 的指令／实际 ROB 队首，并先通过
LSQ 的提交／确认握手才可提交。加载响应的错误
按 ROB 槽位保留到完成，存储确认的错误直接送入 ROB；两者都只在对应指令
精确提交时更新 `error_o`。

分支恢复由带有效标记的 ALU 完成结果触发。ROB 保留分支及更老条目、恢复
逐通道构造的 RAT 检查点。RS、LSQ、完成 FIFO 按 ROB 年龄清除严格年轻项；
恢复同拍的老路径完成结果／AGU 更新会被保留。长延迟 MDU 继续运行，输出用动态
槽位加 8 位代际标记校验，避免旧结果写入复用后的 ROB／物理寄存器。ROB 同时是
`rd/rd_we/new_phys/old_phys` 的唯一按槽位所有者：提交时直接输出旧／新物理寄存器，
恢复时输出分支自身目的映射，并把严格年轻项的新物理寄存器汇总为回收位图／计数。
后端以当前空闲位图与回收位图的并集恢复空闲状态，不经过空闲寄存器
编号压缩、环形空闲列表首尾指针恢复，也不在联合模块中维护第二套重复物理寄存器／逻辑寄存器表。

## 单元门

`tb/unit/rv32_backend_joint_tb.v` 覆盖 RAW/WAR/WAW、长延迟 DIV、MUL 与加载
同周期完成、存储／加载响应端往返、字节转发、检查点恢复、精确
加载／存储错误和停机返回值，并包含 100 周期完成超时与
10,000 时间单位的全局看门狗。`make b09` 保持单发射兼容性，`make join04` 验证
双／四发射代表配置，`make join05` 验证全部 9 组 FE/BE 宽度组合，并同时覆盖
`PHYS_REGS=48/64/96`、`ROB_ENTRIES=16/32/64`。

整机前端为每个取指通道提供独立预测读口。当前实现复制小型 BHT/BTB 状态，并让
所有副本接收相同反馈以保持一致，避免通道 1--3 中的分支被固定成不跳转；
取指前端仍以指令束中最早的跳转预测截断后续指令。
