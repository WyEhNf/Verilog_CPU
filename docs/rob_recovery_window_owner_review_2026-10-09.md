# Private pending recovery and the original ROB window

The measured 21175e7b Tier3 path starts at the pending packet's ROB slot, crosses slot-minus-head and occupancy qualification, then recovery, LOAD selection/wake, RS issue and ALU capture. That freeze is 357.541899MHz. The later 193-parameter class/PC freeze at 680bc691 is still being measured separately. This review does not establish either freeze's final timing.

ROB_RECOVERY_WINDOW_OWNER defaults to zero in the same student_top/core/backend and selects RECOVERY_WINDOW_OWNED in the original ROB. All hierarchy guards and the candidate runner require ROB_RECOVERY_PENDING_OWNER=1. Generic stale-input recovery retains default-zero rejection. The private caller already owns the exact allocated row, with the original full row-valid/GEN reader asserted on every valid recovery edge. The new policy additionally asserts the original modulo slot-minus-head distance is below the original occupancy on every valid recovery edge, including a pending whole-flush edge when reset is absent.

The ROB's allocated window is the occupancy-length circular prefix beginning at head. Reset clears its row validity and occupancy. Ordinary prefix retirement removes the same oldest rows and advances head by that prefix; allocation appends rows at tail and increases occupancy. Recovery clears the younger rows, preserves the resolving branch and all older rows, sets tail to branch+1 and occupancy to branch age+1. Optional direct recovery allocation credits cannot replace the retained branch row. Thus an exact live allocated row is inside that window, including the full-ROB case: the slot distance is at most depth-1 and COUNT_WIDTH retains occupancy=depth. This argument relies on the existing ROB transition invariant, not on tag-valid alone.

Acquisition uses the existing uncanceled ALU redirect and complete ROB identity. Every redirect is excluded from ordinary ALU completion, and distinct MDU/LSQ/store identities cannot complete this branch; the existing producer assertion checks that complete tag. A branch therefore cannot retire on acquisition. There is only one private pending queue. Direct recovery injects its completion and applies on the first pending edge, clearing the owner on that edge. Staged recovery may complete on preview, but recovery_hold suppresses commit and allocation throughout preview/apply; apply preserves the branch and clears the owner before any later retirement/reuse. Reset/whole flush clear pending state, and the original failed-preview and matching-commit fallback remain. No second recovery can kill the branch while this owner is held.

Enabled mode replaces only the repeated age-versus-occupancy acceptance guard with true under that private contract. It keeps recovery_valid, tag-valid/slot range, full identity storage, actual slot/age calculation, oldest-lane selection, selected destinations/checkpoints, younger kill/reclaim, completion, epoch, preview/apply, reset/flush and backpressure unchanged. The backend still presents only pending lane0. The critical control can therefore avoid the subtraction/comparison even though the actual age data is still required by recovery consumers. This adds no FF, cycle, pipeline stage or capacity and provides no STA path exemption. Default-zero mode uses exactly the original arithmetic guard.
