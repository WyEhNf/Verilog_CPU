# MMIO STORE admission factoring after fresh RS timing change

This review is now implemented as the default-off `MMIO_STORE_ADMISSION_ROUTE` policy; its new CPU PPA/IPC are unmeasured. Freeze `8af905db` measured 8973.514135 um² / 294.930876 MHz, with no CPU build/perf/smoke because the frequency gate failed. No canonical profile was replaced. Its new worst path starts in Dcache saved SRAM query control, crosses the LSQ response query, load report metadata selection, completion and ROB query logic, enters LSQ visible selection and byte forwarding coverage, then request-owner validity → MMIO exit distribution → bus read lifecycle. Arrival is 3.331 ns; minimum period is 3.390625 ns. All five reported longest paths have this common source. This replaces the prior worst fresh RS allocation/SUB path, so the disabled-HALT review is not the next timing priority.

Current saved MMIO class is `SAVED_REQUEST_QUERY && any_present_store && !existing_selection_packet.load && existing_selection_packet.address==0x80000000 && existing_selection_packet.relative_mask==0xf`. `any_present_store` suppresses an invalid stale STORE class when a fresh allocation LOAD is offered. A fresh offer requires no present stores, and carries selected_load=1. Thus saved MMIO class true excludes the fresh LOAD alternative and implies the old selection packet is a STORE. The class contains the exact existing address/mask predicates; it is not merely an address prefix or opcode class.

Original owner validity in saved-query mode is `!flush && !recovery && (fresh_without_forward || (found && !wait && (!query_load || query_incomplete_forward)))`. Existing query_load comes from that same existing selection packet. On a saved MMIO class, query_load=0 and fresh_without_forward=0, and the selected source must be the old packet. Thus the exact qualified exit request reduces to `!flush && !recovery && candidate_found && !candidate_wait && saved_mmio_class`. Candidate selection and wait already carry the original transaction ownership/live checks. LOAD forwarding coverage can be eliminated from this STORE-only route without changing a handshake, state edge, tag width or load forwarding behavior.

A possible default-off policy is a new qualified MMIO valid output of the shared LSQ/backend, computed from that factored expression. Core routing could use it only with saved LSQ query/class enabled and DCACHE_REQUEST_PIPELINE=0. A request register must use its own accepted saved owner; never use upstream LSQ class for its output, so the first policy should reject a request pipeline. For all cycles including stale invalid packets, compare this factored signal to `dcache_req_valid && saved_mmio_class` in simulation, and at the core compare to the original exact valid/store/address/line-mask predicate. Preserve complete ACK capture, normal cache traffic and AXI request semantics. Do not use raw MMIO class for bus routing.

Before implementation, inspect candidate_wait, old/fresh packet ownership, selection-live and direct-bypass guards and recovery behavior. A small paired extension of the existing saved-route sample can cover held STORE, stale STORE class with fresh LOAD, full/partial forwarded LOAD and row-generation reuse. This is a future finite sample, not an instruction to run a full correctness suite. Combine only independently justified timing/area changes, lint once, then one full PPA. CPU performance remains gated by both PPA limits and must match the c2a09eaa per-case cycle reference as well as IPC >=0.6000.

The unused-HALT source guard and MSHR payload clear review remain unimplemented. Area margin of this freeze is 26.485865 um², so additional control duplication must be measured; there is no mapped-area prediction for the proposed factoring. Every width retains the same parameterized CPU, shared backend and LSQ.

## Implementation and finite sample

The shared LSQ now exports `dcache_req_mmio_valid_o` with exactly the expression above. The shared backend only forwards that wire. Core selects it when `MMIO_STORE_ADMISSION_ROUTE=1`; top exposes that same parameter, default zero. Core and candidate runner reject enabled policy without saved query/class or with a CPU request pipeline. Existing generic request owner, normal LOAD requests, byte forwarding, complete tag/generation fields, state transitions, ACK registers and AXI bridge are untouched. Every downstream MMIO consumer uses the same final qualified route as before.

On every non-reset simulation edge in saved-query mode, LSQ compares the new factored output to `dcache_req_valid_o && dcache_req_mmio_class_o`, including invalid stale packets and recovery. Core's existing always-active saved-route assertion compares the finally selected route to the original exact valid/store/address/line-mask expression. The class still carries `any_present_store`; it is never a raw address-only route.

Inspection confirms candidate_wait is the selected row's existing response_wait bit; candidate_found is selection_live OR direct selection bypass for the pipelined LSQ, or the original pick-valid for nonpipelined LSQ. The complete generation/live/sent/complete/wait tests in selection_live and the original direct bypass are preserved. A fresh allocation offer requires no candidate and no present STORE, and is a LOAD. Held STORE tickets retain the original packet after ready deasserts. An invalid stale ticket alone cannot make candidate_found true.

One paired BE2/LSQ4 finite sample passed: both DUTs use saved query and phased data owners; their fixtures consume generic-valid/class route versus the new factored output. Public valid/ready-derived handshakes, cycle counts, valid complete request/load payloads, and exact new/old MMIO predicates are compared. It covers the existing directed fresh/held LOAD, partial/full forwarding, delayed store data, full row reuse and stale response, held MMIO STORE/ACK, stale STORE after queue drains followed by fresh LOAD, and recovery guard. It uses RELEASE_CREDITS=2 only to exercise full row reuse; production Tier1 remains RELEASE_CREDITS=0. It does not instantiate cpu_core or AXI bus and does not claim full CPU proof. Evidence: `reports/Tier_shared_LSQ_mmio_admission_protocol_2026-10-09.json`.

The candidate profile `configs/tier1_shared_mmio_admission.json` adds only this routing policy to the measured fresh-data profile. The HALT/source-query and MSHR-clear reviews remain unimplemented. No canonical configuration is replaced until the exact source passes all area/frequency/IPC requirements without per-case performance regression.
