## RS_INVALID_PAYLOAD_PRELOAD ownership and algebra

The CPU guard requires registered elastic dispatch, static local RS rows, no issue-release allocation credits, no allocation/issue bypass, BE_WIDTH<=RS_ENTRIES and the original operand-write policy. This mode is mutually exclusive with rejected RS_QUALIFIED_OPERAND_WRITE. The backend supplies its original d_rs_need as alloc_plan_valid_i; actual alloc_valid_i remains d_rs_need AND the original common d_admit. Thus the actual batch is either zero or the whole planned vector. Actual fire/count/capacity, slot exports, row valid, age relation, source-ready flags, target-live and reset/flush/issue events remain original.

The original kth accepted lane owns the kth free physical row. For every accepted lane all preceding requested lanes have also been accepted; otherwise the original capacity prefix would have stopped before it. Therefore accepted_before equals the planned valid-lane population count for an actual accepted lane. Reuse the existing full-width free_before tree and independently count the original planned lanes; match kth planned lane to kth old-free row. The no-release contract makes these rows old-invalid. Only wide row payload selection uses this earlier plan; actual grants/ranks/slots/write events keep the original calculation. This avoids a second wide hardware selector. Native original actual-grant selectors compare the complete allocation packet at every actual non-reset/non-flush row allocation.

For an old-invalid row, prepare original opcode, pc, full ROB tag, physical destination, immediate/prediction/store metadata, both source values and complete source identities in the existing FFs each edge. For an old-valid row, all immutable metadata/source identities hold; each operand accepts only its original wake event/value. Actual allocation writes precisely the original prepared packet and makes the row valid on the original edge. Ready/target-live/age are still written only on that actual edge. Reset/flush selective kill and retained-row wakes are original. No live field is prewritten, no generation is shortened or fabricated, and no state/stage is added.

Private invalid row data/tag write edges intentionally differ, as do unqualified raw entry metadata/base/tag wires for invalid rows. This is not a claim of equality for all unused internal or diagnostic wires. CPU store-base admission uses original entry_base_ready (valid AND target-live AND original ready AND !flush), recovery/row issue uses original valid ownership, and issue payloads use original ready_candidates/ranks. The actual valid/ready interfaces, accepted public packets and cycles remain the contract. Full original source-write shadows and immutable metadata/full identity shadows compare every live row; parent shadows compare every actual full allocation packet. The whole atomic-plan contract is asserted. Range and full GEN checks in LSQ/ROB remain unchanged; selective recovery keep-count alone does not license dropping range predicates.

## RS_MDU_CLASS_PRESELECT

Each saved row decodes exactly the eight original full opcodes MUL/MULH/MULHSU/MULHU/DIV/DIVU/REM/REMU. For every original issue lane, OR those class bits qualified by the same ready_candidates and ready_rank_match that select the original opcode/operand packet. Their one-row rank ownership makes this equal to decoding the final selected opcode. The all-zero no-selected-row packet has opcode0, outside these eight classes. RS and backend native shadows compare the class on every non-reset raw cycle, including blocked/invalid issue cycles and recovery. MDU candidates, oldest-lane priority, complete selected op/64-bit operands/full ROB tag/physical destination/cancel flag, ready and launch/completion rules are unchanged.

The backend guard requires ISSUE_PIPELINE=0 and allocation bypass0, so the sideband refers to the same original issue stage; no class FF or stage is inserted. Other configurations retain the original selected-op decode. Generic saved-row RS users can use the class sideband with matching stage ownership. This is one shared RS, not a class-specific replacement backend.
