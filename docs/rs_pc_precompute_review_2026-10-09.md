# PC arithmetic before shared RS issue selection

The measured 21175e7b paths cross recovery/LOAD wake and RS issue into execution registers. The operation-class predicate changes remove irrelevant PC target/read arbitration cones from some control consumers, but the actual branch-target output still needs PC+immediate after payload selection. RS_PC_PRECOMPUTE computes that real value before the late issue grant, rather than ignoring its target register or adding a pipeline stage. The 192-parameter c7d94e18 freeze passed original full-core lint only; no PPA was launched for that partial combination. The PC policy is added before one combined PPA.

RS_PC_PRECOMPUTE defaults to zero on the same top/core/backend. The existing RS receives PC_PRECOMPUTE, and the same ALU receives PRECOMPUTED_PC. Nonzero mode requires exact inline immediate metadata; generic RS also requires full opcode and metadata>=32. Each saved RS row derives `{PC+4,PC+immediate}` modulo 2^32 from its original saved PC and immediate. The relative sum uses the actual existing nibble carry-select/prefix helper, including under WORD_SIM. Fresh allocation issue uses the original incoming PC/immediate for the same exact tuple. Source wakeup/identities, readiness, age/rank, lane priority, eligibility, cancellation, row acquisition and release retain original logic.

The tuple is appended above original packet, optional arithmetic32 and comparison3, below original recovery qualification/cancel sidebands. Original low-bit fields and authority retain their positions and meaning. Fresh and saved payload selection/qualification remain unchanged. The optional existing issue stage stores the tuple on the same original valid/tag/capture edge; it adds 64 payload bits per lane only in that already-registered mode. The Tier3 profile retains direct issue, so it adds no FF. No new valid bit, certificate, stage or cycle is introduced.

The ALU uses the selected relative sum for original AUIPC/conditional-branch/JAL target consumers and selected PC+4 for original JAL/JALR link and not-taken next-PC consumers. It retains all opcode-class masks, actual branch/redirect target captures, compact/full prediction rules, old/raw redirect assertions, tag/generation, ready/backpressure, recovery and ordinary completion. Default-zero mode keeps the original ALU additions. Every valid RS-selected tuple and ALU-issued tuple is asserted against full-width sums of its original complete packet, so no derived tuple supplies identity/readiness authority.

One bounded shared-backend pair compares PC0/1 with fixed row arithmetic1/comparison1, target-class compare1, compact completion2, pending owner1 and consuming private capture1. It retains original direct/staged recovery and the existing issue stage, real LOAD-return wake of BNE, four renamed comparisons, ADD/SUB/ADDI, wrapping STORE addresses/ACKs, generation reuse, reset/whole flush, MUL0*0 and precise LOAD error. Two actual AUIPC results add PC wrap and negative immediate, and one actual JAL checks its original link/capture/retirement. Public cycles/valid packets and allocator state plus exact PC tuple/original redirect assertions are checked. This is finite evidence only, not a whole CPU/all-width/formal proof. Raw source-accept counters are not flush-qualified and are never interpreted as architectural apply counts.

The 193-parameter class+PC Tier3 candidate retains all original width/resources, caches/AXI, registered dispatch, register PRF and direct issue. Extra row adders and 64-bit payload selection can increase combinational area, so frequency gain and area are unproven.
