# Saved STORE route and MSHR data owner candidate

The e776571f static-source/saved-state candidate failed both Tier1 PPA gates at 9069.333895 um2 / 290.496454 MHz. It is rejected, with no CPU build/perf/smoke. Its longest path returns to D-cache response/completion, ROB query, LSQ selection/LOAD forwarding coverage, qualified MMIO distribution and a bus read lifecycle register. The better measured 8af905db remains the candidate reference, at 8973.514135 um2 / 294.930876 MHz, itself still short of the frequency gate.

The new configs/tier1_shared_store_route_owner.json starts with that better fresh-data profile, keeps DECODE_STATIC_HALT_CLASS=0, and combines LSQ_SAVED_CANDIDATE_STATE_QUERY=1 with MMIO_STORE_ADMISSION_ROUTE=1. The earlier standalone STORE route trial failed because its new worst path ran through the fresh visible-slot/candidate-found mux before the wait-state query. The saved-state index removes that dependency. These two policies together are intended to remove LOAD forwarding coverage from the STORE-only qualified route without creating the earlier late candidate-state index path. No mapped improvement is assumed before measuring this combination.

The STORE classification includes an existing saved selection, STORE class, exact address 80000000, relative mask f and an actually present older STORE. A fresh LOAD offer requires no present STORE and overrides old wait-state data. The generic request's full forwarding coverage can only suppress a LOAD, so candidate_found AND NOT candidate_wait AND saved_MMIO_class is the same original valid-qualified MMIO route. Saved state reads the same old selected slot whenever candidate_found is true. Original full GEN/tag, selection liveness, flush/recovery, exact MMIO payload, ACK and AXI edges remain intact. The existing production assertions compare both factored route and candidate state to their original queries. See the two earlier policy reviews and finite LSQ samples for their explicit scope; they do not prove this combined whole CPU.

DCACHE_MSHR_DATA_NO_CLEAR=1 targets area by suppressing only unowned data clears in existing banked MSHR payload owners. Every STORE obtains a full initialization before merging or publishing bytes; reset/prefetch still clear lifecycle authority and suppress colliding lower-priority writes. All 128 data bits, masks, victim payload, full identity and edges are retained. See docs/mshr_unowned_clear_review_2026-10-09.md for consumer and collision details. The finite paired PREFETCH=1 cache sample is the only new protocol sample for this candidate; no Boolean identity test or broad correctness suite is added.

All widths still use the same parameterized cpu_core/rv32_backend_joint/cache. Canonical profiles and defaults are unchanged. The candidate must pass one original structural lint and one frozen official PPA before CPU build/perf. Require area <=9000, frequency >=300, IPC >=0.6000 and no per-case cycle regression versus c2a09eaa (12249/23982/231173/455096/7515/9007). Only then run one correctness_array_test1 smoke. None of the older Tier2/Tier3 metrics proves this new source; those freezes remain separately preserved.
