The original memory bridge selects a saved local error's full8-bit ID and32-bit line address or the original external response's full ID/address. That selection happens before the cache's ID lookup, address comparison and response-class/output-slot predicates. DCACHE_SPLIT_MEMORY_RESPONSE_QUERY defaults to0 in the shared top/core and selects SPLIT_MEMORY_RESPONSE_QUERY in the same nonblocking D-cache. Top/core/runner guards require cached nonblocking memory. No alternate CPU, narrowed identity, pipeline, FF, transaction, capacity, benchmark hook or STA exception is added.

The existing bridge exports both original metadata tuples and one-hot source selection: low source is its retained local error, high source is the external return. Local error has error=1; external source has its original error bit. These wires reuse the original saved address/ID and do not acquire additional ownership. Selection is `{!local_error,local_error}` even when public response valid is0. This distinction is essential: the original cache's response_found and mem_resp_ready are not response-valid-qualified. Replacing source selection by valid-qualified candidates would alter invalid-cycle ready behavior and is deliberately avoided. Public bridge packet selection, valid, ready, data, error, request admission and local error lifetime are unchanged.

For each source and each physical MSHR row, the cache computes original full-ID equality plus original valid/sent, original32-bit expected-address equality and original row class. A full-width ID-to-row comparison retains range behavior even for out-of-range IDs; no truncated index or speculative certificate is used. The original predicates are then distributed algebraically before the source mux. With F=valid&&sent&&ID==row, A=original address match and B=writeback&&(source_error||!A), the LOAD claim is F&&((!writeback&&!store&&!prefetch)||(B&&!store)). The store response claim is F&&writearound. Found/address-match/writeback-failure/claims reduce across rows per source, then the original one-hot selection chooses their scalar results. Actual response emission still uses the original public response valid.

Output reservations preserve the original rules separately from emission: an around STORE reserves its ACK slot; a non-around/nonstore/nonprefetch row reserves the LOAD slot, including a successful writeback phase that does not itself emit a LOAD. The original successful-writeback reservation is retained to preserve cycles, despite appearing unnecessary for its payload. Thus new response_needs_output is original ACK/load reservation classes combined with original slot-free state, not a new scheduling policy. Actual metadata/data selection and all MSHR/array/waiter/reply writes continue to use the original selected full tuple/index. No payload, priority, response acceptance, completion/error or held-result edge is changed.

In enabled simulation mode, every non-reset edge checks one-hot source selection and equality of the original selected full ID/address/error tuple. It then compares all six raw original predicates: found, address match, writeback failure, LOAD/store emission and output reservation. These checks include invalid response cycles. The simulation-only original lookup/address read/class expressions are retained independently; they are not reconstructed from the optimized predicates. Default-zero mode keeps the original lookup and all class formulas. Timing improvement, added combinational area and latest-source tier acceptance remain unproven until official measurement.
