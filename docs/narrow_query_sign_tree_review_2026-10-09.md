# Narrow request query, conditional sign correction and bounded polarity tree

These are optional implementation policies of the same parameterized CPU/backend. The previous measured Tier1 candidate (`1c0a5d2a`) remains rejected at 9191.091475 um2 / 243.983798 MHz. Neither its old IPC reference nor the accepted historical Tier2/Tier3 metrics apply to this source. The saved-route timing fixes from `8b9d2d01` are included; their preflight was lint-only.

## Narrow D-cache query owner

The LSQ request owner already constructs each valid 128-bit request data line as a zero-padded relative 32-bit word inserted at address[3:0], truncating overflow exactly as a 128-bit left shift. Its relative word is load forwarding data or store operand data, with the existing fresh-load forwarding certificate and held-forward choice. A new output exposes that unqualified word through the existing LSQ/backend/core instances. Invalid words have no storage or side-effect authority.

With DCACHE_NARROW_REQUEST_WORD=1, the synchronous cache input owner retains 85+2*TAG_WIDTH bits instead of 181+2*TAG_WIDTH: the same full ROB/LSQ tags, 16-bit mask, address, class/size/unsigned flags and a relative 32-bit data word. The accepting edge and enable are identical. After capture the existing insert32 helper reconstructs the exact original 128-bit data from the saved word and saved offset. Cache hit, MSHR merging, writeback/refill and all later consumers therefore receive the same valid owned data. No data-bank hold or store coalescing word was narrowed. The original full-width generic cache query remains mode zero; mode one asserts that every valid incoming line equals the supplied raw-word insertion. The CPU guard requires ENABLE_CACHES, MSHRS>1, SRAM tags, and DCACHE_REQUEST_PIPELINE=0, so the raw word cannot bypass another request-register owner.

One paired CACHE16/ways2/MSHR2/WAIT2 sample compares policies zero and one. Its eight accesses cover held cold SB/SH/SW merging at different offsets, held ACK/RFO/response, merged word hits, and two colliding loads evicting the exact dirty merged line. Valid public handshakes and payloads, plus the valid internal held query data, agree. An existing bounded BE2/LSQ4 fixture also checks every valid raw word against the original 128-bit request data through fresh/stalled loads, partial/full forwarding, row reuse, stale response, MMIO and recovery. The native sample uses the unchanged original SRAM model but is two-state; it is not a whole-cache/CPU or four-state proof.

## Direct conditional sign correction

For `y = negate ? (~x + inc) : x` modulo 2^32, bit zero flips exactly when negate AND NOT inc. A higher bit i flips exactly when negate AND (NOT inc OR any lower x bit is one). When inc=1, adding one to the complement preserves the lowest set bit of x and all lower bits, flipping all higher bits. When inc=0 it is plain ones-complement. Negate=0 preserves every bit regardless of inc. The formula also preserves x=0 and the signed-minimum two's-complement boundary.

The new helper computes lower-bit OR prefixes with parallel shift distances 1/2/4/8/16, then XORs the flip masks. Two existing control-tree leaves per flag bound each flag to sixteen bit consumers. MDU_PREFIX_SIGN_CORRECTION=1 selects this helper for both request absolute magnitudes and the actual registered finishing sign correction. It changes no iteration, completion, division-zero/overflow, tag, recovery or ready state. The shared feedback adder remains unchanged. High-half signed multiply retains its original inc=(low magnitude word==0), which requires both inc=0 and inc=1. No area saving is claimed from the existing unused corrected_result/final_value diagnostic temporaries.

One paired same-MDU sample (DIVZERO_REMAINDER_REUSE=1 in both, varying only PREFIX_SIGN_CORRECTION) passed seventeen fixed arithmetic points, exact response tags/physical destination/ready-write flag and completion cycles, plus a held result. The added high-half cases distinguish zero/nonzero lower magnitude carry, mixed signed/unsigned and unsigned products. This is a small boundary sample, not exhaustive arithmetic or CPU perf evidence.

## Bounded alternating-polarity control tree

The old tree restores a positive representation then inverts it again at each internal negative subtree. The new optional common-module BALANCED_POLARITY policy uses a filled four-way tree with the smallest even number of inversion stages whose leaf capacity covers the requested count. A virtual positive root drives at most four first-stage inverter inputs per bit. Every actual internal driver owns at most four child inverter inputs; every output has its own final real inverter, is positive after the even depth, and owns the same original consumer group. Real inverter instances retain keep/keep_hierarchy, so synthesis cannot merge sibling distribution drivers or expose a parent to the wide consumer group. No extra padded driver is instantiated. The four-way bound is local to each tree; repeated trees and other direct users of a source still contribute additional source loads, and Fmax requires measurement.

For L leaves and even depth D, the ideal per-bit inverter count is sum(ceil(L/4^i), i=0..D-1), with D=2 for L<=16, D=4 for L<=256, etc. The exact old elaborated Tier1 hierarchy contains 8478 theoretical control-tree inverters and suggests 1243 fewer with the new shape. This is a source-shape count before mapping, dead/constant leaf elimination, or changes in the next profile. It does not measure physical area or frequency. L<=4 retains the same count/depth; L=8 changes seventeen to ten drivers per bit, and L=32 changes seventy-three to forty-three. Shorter paths and fewer real drivers justify combining this with the two data optimizations for one full evaluation.

The profile field balanced_control_tree is a shared implementation policy, matching the existing compact_control profile mechanism. The runner updates both frozen definitions headers, whose common-module default remains zero in the main worktree. balanced_control_tree and compact_control are mutually exclusive. The CPU, backend, widths and ownership rules remain shared. A twelve-vector native sample on WIDTH9/LEAVES4,8,22,64 compared all positive leaves with the original and expected repeated input, using actual RTL without the WORD_SIM shortcut. No new state or cycles exist.

## Evaluation order

Freeze one combined profile, run original structural full-core lint once, then one full official PPA. No separate PPA of the intermediate narrow/sign/tree candidates. Build and six-case perf run only after PPA passes both 9000 um2 and 300 MHz. Acceptance additionally requires the exact candidate's IPC>=0.6000, no per-case cycle regression against the IPC-passing shared baseline, and correct answers/instruction counts/assertions. Only then run one correctness_array_test1 smoke. If PPA fails, skip build/perf/smoke and preserve accepted configurations. No whole correctness suite or geometry sweep is authorized or needed here.
