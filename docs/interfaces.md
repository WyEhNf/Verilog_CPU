# H-01/S-01 接口契约

本文件冻结 H-01/S-01 的公共接口规则。所有后续 RTL 单元只引用 `rtl/rv32im_defs.vh` 中的定义，不在各自模块中重新声明同名操作码、标记或优先级。

## 参数和位宽

默认配置为 `FE_WIDTH=1`、`BE_WIDTH=1`、`PHYS_REGS=64`、`ROB_ENTRIES=32`。默认物理寄存器地址宽度为 6 位，ROB 槽位宽度为 5 位，ROB 代际宽度为 8 位，完整 ROB 标记宽度为 16 位。

ROB 标记的压紧顺序为 `{generation, slot, kind, valid}`。只有 `valid=1` 且 `kind`、`slot`、`generation` 同时相等时，标记比较才成功；槽位相同但代际不同的旧完成结果必须丢弃。

## 压紧总线字段顺序

所有跨模块指令束使用压紧总线，不使用端口非压紧数组。当前冻结的字段顺序如下，左侧为高位字段：

| 指令束 | 压紧顺序 |
| --- | --- |
| `FetchPacket` | `epoch, btb_hit, pred_kind, pred_target, pred_taken, inst, pc` |
| `DecodedInst` | 由代次、预测信息、原始指令／PC、控制字段、立即数和寄存器字段组成 |
| `RenamePacket` | 由代次、预测／访存字段、立即数、源操作数、物理／逻辑寄存器、ROB 标记、PC／指令和操作／类别组成 |
| `IssuePacket` | 由代次、访存／控制字段、立即数、源值、物理目标、ROB 标记、PC 和操作／类别组成 |
| `ExecResult` | 代次、分支结果、访存信息、结果值、物理目标和 ROB 标记 |
| `MemoryRequest` | 有效位、加载／存储属性、地址、大小／符号／掩码、写数据、ROB 标记和 LSQ 标记 |
| `MemoryResponse` | 有效／错误位、缓存行地址、128 位缓存行数据、事务 ID、ROB 标记和 LSQ 标记 |
| `CommitRecord` | 有效位、存储元数据、写回值、rd/rd_we、原始指令和 PC |

未使用通道的 `valid` 必须为 0。多通道指令束只能存在连续的有效前缀，不能出现通道 0 无效而后续通道有效。

## 有效／就绪握手

传输只在时钟上升沿前 `valid && ready` 时发生。当 `valid=1 && ready=0` 时，发送方必须保持完整载荷和标记不变；接收方不得消费或产生副作用。冲刷优先清除年轻推测项，旧响应在写状态前必须通过标记／代次存活检查。

## 同周期优先级

公共优先级从高到低为：停机／错误冻结、冲刷、重定向、写回、提交、存储可见。相同优先级的多个请求由最老的有效 ROB 标记决定。该顺序用于后续前端、ROB、完成通路和缓存连接，不能由单个模块临时改写。
