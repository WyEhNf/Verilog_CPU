# 分配确认前的新鲜 RS 候选载荷

组合 Tier1 冻结版本 `a7e64b80` 测得 8962.127155 um²、274.678112 MHz，面积通过而频率失败。未运行该冻结版本 CPU 构建／性能／冒烟测试，IPC 未知。最差实测路径从指令缓存 SRAM 输出，经架构源译码、RAT／PRF 预览、`d_replace_rs_demand`、ROB 分配接收、新鲜 RS 包屏蔽、SUB 控制和整数加法器。终点 `_116076_/D` 为寄存整数值第 31 位：映射 QN `_000829_` 驱动反相器，输出为 `alu_exec_value[31]`。到达时间 3.5808 ns，报告最低周期 3.640625 ns。这是实测分配控制路径，不代表全部操作数路径。

`RS_FRESH_DEFAULT_LANE_DATA=1` 是同一 `student_top` → `cpu_core` → `rv32_backend_joint` → 共享 `rv32_reservation_station` 的默认关闭参数，要求既有分配发射旁路。只改变新鲜载荷选择器的空闲数据约定。原实际许可、输入就绪排名、发射有效性、保存行选择、已接受分配槽位及释放计数不变。

对一条发射通道，原许可因每个就绪输入通道获得不同累计排名而独热。令 G 为真实许可，新鲜有效性仍为 OR(G)。多于一条分配通道时，k>0 的数据许可为 `D[k]=G[k]`，通道零为 `D[0]=!OR(G[k>0])`。G 非零且独热时 D=G，因此每个有效新鲜包逐位相同。G=0 时，显示通道 0 候选包，但它无效。只有一条分配通道时，同一选择器直接化为通道 0 包，操作码或操作数数据前不再有分配接收门。未按发射宽度选择不同 CPU，只是同一选择器的普通参数化化简。

原 `fresh_lane_allowed` 仍选择新鲜／保存数据。新鲜恢复取消／限定边带保持零，保存发射载荷和唤醒选择不变。实际分配槽位 generation 仍经限定并保留在包中。仿真以原完整载荷宽度断言许可独热及有效包与原选择器准确等价。

无效原始数据可能改变组合功能单元路由／ready。后端 MDU 候选包含 `rs_issue_valid`，ALU 发射有效性包含 `rs_issue_valid` 及路由，恢复年龄谓词包含 valid，RS 发射 fire／释放要求 valid 和 ready。在支持的不借用释放信用模式下，allocation fire 依赖输入分配有效性及保存容量，不依赖下游 issue ready。因此空闲数据不能创造已接收分配或执行，有效包及对应输入就绪不变。运行器／核心／RS 拒绝在无分配发射旁路时启用；既有旁路约束要求直接静态分派，且无释放信用或发射流水线。

一组有限配对样例用同一 RS、参数 0/1 覆盖宽度 1/2：无效候选、阻塞新鲜载荷保持、立即消费新鲜包、更老未就绪分配后同周期唤醒、清除边界、满容量拒绝、复位和行复用。逐周期比较真实 valid/fire、完整有效包（含完整标签、物理目的、两个操作数、存储数据、元数据和槽位）、行所有权、占用、槽位及释放状态。它是采用 WORD_SIM 调度的原生二状态 Verilator 样例，不是四状态或整 CPU 证明。见 `reports/Tier_shared_RS_fresh_data_protocol_2026-10-09.json`。

新配置 `configs/tier1_shared_fresh_data.json` 在已测所有者／树组合配置上增加此策略，预期移除单通道 ALU 数据路径前实测晚到分配屏蔽。准确冻结版本测量前，不宣称面积／频率／IPC 改善。运行一次结构静态检查及一次完整官方 PPA；面积 <=9000、频率 >=300 后才构建一次并执行六项官方性能程序。要求 IPC >=0.6000，且相对 c2a09eaa 参考（12249/23982/231173/455096/7515/9007）无逐项周期回退。全部验收门通过后运行 array1 一次。历史 Tier2/Tier3 配置及默认值仍归于既有源码冻结版本。
