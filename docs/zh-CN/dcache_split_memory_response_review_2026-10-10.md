原主存桥在缓存 ID 查询、地址比较及响应类别／输出槽谓词之前，先选择已保存本地错误的完整 8 位 ID 和 32 位行地址，或原外部响应的完整 ID／地址。DCACHE_SPLIT_MEMORY_RESPONSE_QUERY 在共享 top/core 中默认为 0，选择同一非阻塞数据缓存的 SPLIT_MEMORY_RESPONSE_QUERY。top/core／运行器约束要求带缓存的非阻塞主存模式。不增加替代 CPU、收窄身份、流水线、触发器、事务、容量、基准专用钩子或 STA 例外。

既有主存桥输出原有两组元数据及独热源选择：低位源为保留的本地错误，高位源为外部返回。本地错误的 error=1；外部源保留原错误位。连线复用原保存地址／ID，不取得额外所有权。即使公共响应 valid 为 0，选择仍为 `{!local_error,local_error}`。此区别很关键：原缓存的 response_found 和 mem_resp_ready 不受响应有效位限定；若改为受 valid 限定的候选，会改变无效周期 ready 行为，因此明确避免。公共桥包选择、valid、ready、data、error、请求准入和本地错误生命周期不变。

缓存为每个源、每条物理 MSHR 行计算原完整 ID 相等条件、原 valid/sent、原 32 位预期地址相等条件及原行类别。完整宽度 ID 与行比较在 ID 越界时也保留范围行为，不使用截断索引或推测证书。随后将原谓词按代数等价方式提前分布到源多路选择器前。令 F=valid&&sent&&ID==row、A=原地址匹配、B=writeback&&(source_error||!A)，则 LOAD 声明条件为 F&&((!writeback&&!store&&!prefetch)||(B&&!store))，存储响应声明条件为 F&&writearound。每个源先跨行归约 found／地址匹配／写回失败／声明条件，再由原独热选择选出标量结果。实际响应发布仍使用原公共响应 valid。

输出预留与发布分开，保留原规则：绕过分配的 STORE 预留 ACK 槽；非绕过、非存储、非预取行预留 LOAD 槽，也包含本身不发布 LOAD 的成功写回阶段。尽管对其载荷看似不必要，仍保留成功写回的原输出预留，以保持周期。因此，新 response_needs_output 是原 ACK／加载预留类别与原空闲槽状态的组合，不是新调度策略。真实元数据／数据选择及全部 MSHR／数组／等待者／回复写入仍使用原所选完整元组／索引。不改变载荷、优先级、响应接收、完成／错误或保持结果边沿。

启用模式下，仿真在每个非复位边沿检查独热源选择，以及与原选中完整 ID／地址／错误元组相等；再比较全部六个原始谓词：found、地址匹配、写回失败、LOAD／存储发布及输出预留，也覆盖无效响应周期。仅用于仿真的原查询／地址读取／类别表达式独立保留，不从优化后谓词重建。默认零模式保留原查询和全部类别公式。时序改善、新增组合面积及最新源码三档验收，均须官方测量后才能确认。
